Fixes & closes #465
Summary
Audit of all randomness feeding BIP39 seed generation in apps/mobile, prompted by the Coldcard Mk3 entropy disclosure. Nine original findings fixed, plus follow-up hardening for weak manual input, seededRandom, and a large-N statistical audit suite.
The default path was already sound. Native bdk_ffi → ThreadRng → OsRng → getrandom(2), confirmed by disassembling the shipped .so. No Math.random in any key path.
The optional dice and coin paths were broken. One hard-blocked users; the other silently under-delivered entropy. They now use SHA-512 conditioning with optional device mixing (default on).
Findings (original audit)
#
Severity
Finding
1
Critical
Dice softlocked forever on face "1". Buttons emitted the array index (0–5), so while every roll was 0 the accumulator stayed 0n → 8 bits, never reaching 128. Counter climbed, bar never filled, no error. Every leading "1" was silently discarded.
2
Medium
Dice lost 6.19 bits (12-word) / 5.84 bits (24-word). Termination on bit length confined the value to [2^120, 6·2^120), so the leading byte took 5 of 256 values. Residual 2^121.8 — not brute-forceable, but a real defect in an entropy-assurance feature.
3
Medium
Roll-count collision: [1, 4×47] and [4×47] gave byte-identical entropy. 48 rolls = same seed as 47, so the paper log couldn't reproduce the seed.
4
High
Coin had no debiasing, and both buttons were identical gray circles inviting one-sided tapping. At p=0.8 → 184.8 bits for a "256-bit" seed. Unbounded shortfall, reported as full strength.
5
Medium
Manual entropy replaced the CSPRNG entirely — seed strength was a pure function of user input quality.
6
Medium
drawing was selectable but its handler was case 'drawing': { break }. Tap generate, nothing happens.
7
Low
randomNum() divided by 2^32-1, so a maximal draw returned exactly 1.0 → index past end → undefined word on the seed-confirmation screen.
8
Low
AES-CBC IV came from uuid.v4(): 122 bits, 6 fixed at known positions.
9
Low
No distribution tests. Existing coverage used '0'.repeat(128) — uniform inputs can't catch a distribution bug, which is why 1–3 shipped.
Figures derived analytically and cross-validated by Monte Carlo (200k–300k trials).
Changes (original)
New utils/entropy.ts — SHA-512 conditioning, CSPRNG mixing, rejection-sampled randomIndex, bias detection. Findings 2–5 shared one root cause (conditioning implemented ad hoc inside React components) and are fixed together.
entropy/dice.tsx — terminates on roll count; buttons pass the printed face; undo; bias warning; mix toggle
entropy/coin.tsx — hashed conditioning; visually distinct 0/1 faces; undo; bias warning; mix toggle
utils/crypto.ts — randomNum divides by 2^32; randomIv uses randomBytes(16)
config/entropy.ts — drawing removed, dead case blocks deleted from both flows
locales/en.json — new keys; dice/coin descriptions corrected
__mocks__/react-native-quick-crypto.ts — createHash/randomBytes delegate to node:crypto
Follow-up hardening
Additional review findings addressed on top of the original audit:
Severity
Change
High
Weak / patterned input (not only first-order bias) is detected; unmixed continue requires an explicit confirmation. Copy no longer claims hashing "rescues" entropy when mix is off.
High
Preview uses the real bit width and is labeled so it is not mistaken for the final seed (especially when mix is on).
Medium
Helpers enforce minimum roll/flip counts (allowPartial only for live preview).
Medium
Recorded dice/coin log is shown for the paper-trail path; undo remains available after completion.
Medium
seededRandom uses the same [0, 1) contract as randomNum (divide by 2^32) to avoid Fisher–Yates holes in coin selection.
Medium
Mix folds crypto.getRandomValues (same CSPRNG surface as randomIndex / randomNum).
Low
Frozen hash KATs, mix byte-count coverage, pattern/weak helper tests.
Low
Multisig generate passes 'english' explicitly; generateMnemonic documents the English (BDK native) vs non-English (getRandomValues) split.
Large-N entropy audit
New opt-in suite under apps/mobile/tests/entropy-audit/:
Sources: CSPRNG, dice, biased dice, coin, biased coin, mix, and a deliberately broken restricted-byte canary
Checks: byte χ², bit balance, serial correlation, collisions (skipped for biased input generators)
Commands: pnpm test:entropy · pnpm entropy:audit (ENTROPY_AUDIT_SAMPLES, default 5k for the audit script)
Default path note: English new Mnemonic() still uses native BDK RNG (Jest mocks BDK, so CI does not exercise that .so path). Non-English and mix paths are covered by the JS CSPRNG samplers.
Design decisions
Hashing over arithmetic conditioning. Lossless base-6 → base-2 needs rejection sampling, which discards user rolls. SHA-512 is uniform by construction and matches Coldcard and Sparrow. Hashing does not add entropy — unmixed seeds are only as strong as the user's input.
Dice buttons pass the printed face (1–6), not the index. Digit conversion happens inside entropyFromDiceRolls, so the sequence the user writes down is the sequence hashed. Offline format: SHA-512("dice:" + rolls.join(","))[0 .. bits/8] (and "coin:" + concatenated flips).
Device mixing defaults on, but is a visible toggle. Mixing means the seed can't be reproduced from the paper log. Some users pick dice for exactly that verifiability, so the trade-off is surfaced rather than decided silently. Weak unmixed input now requires confirmation.
Beyond audit scope
Locale roll counts were wrong. 18 words needs 75 rolls (said 74), 24 needs 100 (said 99) — ceil(256 / log2(6)) = 100. Strings now derive from the same arithmetic as the code.
The quick-crypto mock returned a fake 32-byte digest. Conditioning tests are meaningless against a stub hash, and 32 bytes can't cover 256-bit output.
Test plan
Generate 12/24-word seed with entropy none (English and another wordlist)
Dice: complete required rolls, confirm recorded log, continue with mix on
Dice: turn mix off, enter patterned/biased input, confirm Alert, verify warning copy
Coin: same as dice for mix on/off and weak input
Undo after completion still works

pnpm run check
pnpm --filter @satsigner/mobile test:unit
pnpm --filter @satsigner/mobile test:entropy
