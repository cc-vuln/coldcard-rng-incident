I instrumented the Mk4 firmware at the point where it reads the STM32 hardware RNG, then requested the same 32 bytes used by seed generation.
On 5.6.0, I observed exactly eight hardware reads—direct proof that the seed request reached the TRNG.
On the affected firmware, the same test would have shown zero hardware reads while the bytes came from MicroPython’s software PRNG. This is a straightforward real-device path test, not statistical guessing about whether the output “looks random.”

Why wasn’t a test like this already part of COLDCARD’s test suite and routinely run on real devices?
