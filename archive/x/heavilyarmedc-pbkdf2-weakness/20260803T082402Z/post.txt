According to Greg Maxwell Bip 39 uses an insufficient key derivation function.

BIP 39 mnemonics go through a PBKDF2-HMAC-SHA512 with 2048 iterations (for seed derivation). 

What this means is that it takes the input (randomness or entropy) and combines it with a salt (an optional passphrase). and then an HMAC-SHA512 hash functions is run on this 2048 times in a chain:

Output of round 1 becomes input to round 2 and so on.

This is ESPECIALLY relevant when the quality of the entropy provided as the input is poor...because...

PBKDF2 is compute-bound (CPU-oriented) and not memory-hard, meaning that it uses almost no RAM and consists of simple, highly parallelizable hash operations (HMAC-SHA512). The only thing performing this function requires is CPU time.

This means that a modern high-end GPU can compute a very large number of PBKDF2-HMAC-SHA512 (with 2048 iterations) per second.  

Specialized hardware like ASICs or FPGAs could be designed specifically for this tasking at an even higher efficiency because there is very little memory requirement per operation.

TLDR after reading the opinions of the experts, the weakness of PBKDF2 indicates that BIP 39 is something you should NEVER use without providing high quality, OS level entropy that was securely generated by a computer as an input. Computers can easily and cheaply guess these kinds of seeds really quickly.
